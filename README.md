# 四柱八字 × 節氣 × 紫微斗數

Next.js App Router／TypeScript 的文化探索網站，保留深色金色視覺與手機版閱讀。沒有資料庫或登入要求。

## 開發與驗證

已驗證 Node.js 24.19.0、npm 11.9.0；Node 的 ICU 78.3／IANA tzdata 2026b。瀏覽器歷史時區版本可能不同。

```bash
npm ci
npm run dev
npm run lint
npm run typecheck
npm test
npm run build
npm run test:e2e
```

端對端測試啟動正式伺服器於 3100，使用系統 Chromium。其他機器請設定 `CHROMIUM_EXECUTABLE_PATH`，或調整 Playwright 的 executablePath 使用已安裝瀏覽器。請先建置，且勿同時使用同一份 `.next` 跑 dev 和 build。

## 入口與架構

- `/paipan`：八字；`lib/bazi.ts` 計算四柱、藏干、十神，保留既有結構解讀卡片。
- `/ziwei`：獨立紫微入口；`lib/ziwei.ts` 明示換日、閏月、生年四化與大限約定。十二宮、主輔星與四化以原生 dialog 解釋，支援鍵盤及手機。
- `/explore`：人工城市標籤與兩軸計分試算；八字結果也能帶入當次命盤指標。
- `/result`：保留舊有查詢網址相容性；沒有日期時不預設出生資料，無效日期顯示錯誤。
- `components/paipan/BirthForm.tsx`／`lib/birthTime.ts`：共用輸入元件和時間換算邏輯；兩種排盤不自動共用使用者資料。
- `data/cities.ts`：出生城市與氣候探索目錄分開；含測站、共同期間、指標、機構及來源網址的待驗證常值資料結構。
- `data/ziweiMeanings.ts`：按實際宮位、主星和輔星組合變化的文化解讀，包含可能表現、限制及觀察方向。
- `tests/`：排盤及時間邊界測試；`tests/browser/`：實際計算、資料帶入、DST、互動視窗及手機閱讀測試。

新增系統可獨立放在 `app/<system>/page.tsx`，不需要改寫八字或紫微。尚未建立塔羅內容。

## 資料與約定

1900–2100 年內，年柱依出生瞬間交立春切換，月柱依十二「節」切換；中氣不切月。日／時柱依出生地民用鐘錶（含夏令時間）或使用者啟用的真太陽時，午夜與 23:00 換日可選。沒有人工日柱偏移值。

國農曆與節氣使用固定版本 lunar-typescript；天文公式產生的中國曆法時刻以 **固定 UTC+8** 轉為絕對瞬間，不誤套上海歷史夏令時。全部節氣目前標為公式估算，沒有冒充官方曆表。出生地的民用日期對照中國農曆，不改用該瞬間的 UTC+8 日期；海外農曆日期約定應先與所比較工具確認。

紫微安星使用固定版本 iztro 預設規則，農曆正月切年；八字預設午夜換日，紫微預設 23:00 換日，各自可改。閏月提供全月沿用本月及「十五日（含）前本月、十六日起下月」兩種約定。大限按五行局起始虛歲、陽男陰女順行／陰男陽女逆行；傳統順逆排盤規則與性別認同分開選擇。

歷史時差使用 Temporal／宿主 IANA 資料。回撥重複時間必須選第一次或第二次；跳時、歷史跳日不存在的時間會拒絕。明確啟用手動時差可改成固定時差解讀，並顯示覆蓋警告。1970 年前資料完整性需另核。真太陽時採城市中心經度＋均時差近似，不要求使用者查經度；它不改變出生瞬間或立春／節切換。

寒熱／燥濕沿用參考版透明啟發式指標：−3..3，≥2 或 ≤−2 才判偏性。城市人工標籤 −2/0/+2，每軸 `max(0, 4 − |互補目標 − 城市標籤|)`，合計 8 分；逐步顯示理由，**不是適居機率**。國家僅彙整收錄城市的平均探索分及城市清單，不宣稱國家氣候。全部城市仍為探索狀態，正式分數未啟用。職業筆記與命盤、城市計分完全分開。

詳見 [公式、Sites 比對與資料限制](docs/methodology.md)。

## 隱私與套件

新表單在瀏覽器內計算，不把出生資料放進網址、不自動保存。只有主動按「帶入資料」才把資料暫存於目前分頁的 sessionStorage；另一入口仍需手動按帶入，讀取後移除；接收入口保留自己的換日與閏月規則。舊 `/result?…` 僅維持相容；若自行使用查詢網址，資料會出現在網址及伺服器請求，建議使用新表單。

參考 ZIP、履歷與本機附件沒有納入儲存庫；測試只含使用者明示要求的匿名排盤案例及合成邊界日期，沒有個人姓名或資料檔。

Next.js 已升級至 15.5.27 並同步 lockfile。PostCSS、nanoid、source-map-js 使用相容修補版本 overrides；目前 production audit 無漏洞。開發工具鏈的 braces/fast-glob 仍有 registry advisory，沒有為消除報告而降版 ESLint 或停用檢查。
